# DiagramTeX interface system: "drafting table"

## Intent
- **Who:** someone writing a paper, problem set or lecture notes who needs a figure in their LaTeX. They come from a `.tex` file and go back to one.
- **Task:** draw a precise figure and get clean TikZ out of it.
- **Feel:** a drafting table with engineering paper, ink and a red pencil. It should be quiet, exact and warm. It should not feel like a SaaS dashboard.

## Signature
**Centimetre rulers** run along the top and left edges of the canvas, in TikZ coordinates with y pointing up (`#rulerX`, `#rulerY`, drawn by `drawRulers()` in `js/app.js`).
- The tick step adapts to zoom: 0.25 → 500 cm, with labels at least 56px apart. Steps of 1 or 2 cm get quarter subdivisions; steps of 5 get fifths.
- The selection's extent is shaded on both rulers in a red-pencil wash.
- A red hairline marks the cursor position.

**Logo:** "Node to Node", a coral round node and a blue square node joined by an indigo backslash edge (lavender `#F1EFFF` on dark). Kit, colours and rules live in `design/logo/` (`GUIDELINES.md`; early concepts in `concepts/`). In the app it appears in three places:
- **Top bar:** the mark (20px) followed by the outlined Inter Display Bold wordmark; below 1361px only the mark shows.
- **Loading screen:** an inline `#splash` in `index.html` paints the paper colour at once. The mark fades in only after 150ms, so fast loads never flash it; while it shows, the edge draws from the round node to the square, holds, then lifts off; it stays still under reduced motion. It's lifted on `load` plus fonts (at most 1.5s more), never later than 8s.
- **Icons:** favicon (small cut, edge lightens in dark tab bars) and the app icon (indigo tile).

**Colour restraint:** apart from user content and the logo, the only colour in the interface comes from the two pens. Active tools and menu highlights use ink, not an accent hue. Segmented controls are a recessed track with a raised selected segment; every track uses 3px padding and a 3px gap between segments (2px felt cramped, 4px looked worse). The raised segment is one knob per switch (`js/segthumb.js`) that slides to the new choice in 220ms (eased out, width and height following), so a switch reads as one control rather than buttons lighting up; a switch rebuilt by the click that changed it (properties panel, export menu) starts its knob where the old one was. The knob appears in place on first sight and when a hidden switch shows again, and is still under reduced motion.

## Appearance
- Appearance is System / Light / Dark (a deliberate override of HIG dark-mode.md), an icon-only segmented control (monitor, sun, crescent moon) at the right end of the top bar. At ≤1100px only the current icon shows and clicking it cycles System → Light → Dark. The choice is stored in localStorage `diagramtex.theme`; an inline head script resolves it to `data-theme` on `<html>` before the CSS loads, and System follows `prefers-color-scheme`. Dark redefines the same tokens on `:root[data-theme=dark]`.
- The drawing sheet, page sheets and the typeset document page stay light (`--canvas`, softened in dark) so user colours read correctly; `.doc-page` re-declares the light tokens for everything drawn on it.
- `prefers-contrast: more` strengthens rules and promotes `--pencil` to `--graphite`.

## Depth and shape
Hairline rgba rules and rounded corners: `--r-sm` 4px, `--r` 6px (buttons, inputs, segmented tracks, menu rows), `--r-lg` 10px (popovers, menus, cards), `--r-xl` 18px (modals: their head buttons sit 12px in, 6 + 12). Corners nest concentrically: a shape inset N px inside another takes the outer radius minus N. Segments are 3px inside a 6px track with 3px padding (radius `calc(var(--r) - 3px)`). Menus (context, dash/width, select, LaTeX autocomplete) have 4px padding and 6px rows inside a 10px shell. Selected rows are marked by fill, not an edge bar, because a bar does not sit well on a rounded row. Every menu (context, select, dash/width) highlights the hovered row the same way: the `--well` tone, text and icons unchanged; destructive rows turn the red pen. Submenus sit 4px clear of their parent, first row level with the row that opened it, with no icon column. Tool flyouts have 8px padding on every side and 14px corners (their 6px buttons + 8), section titles inset 4px. A flyout taller than the window stops 8px from its top and bottom and scrolls inside (`overscroll-behavior: contain`); its scroll bar is a thin 4px thumb whose track stops 14px short of each end, so it never runs into the rounded corners. Square corners were tried and rejected as less friendly; chamfered (diagonal-cut) corners were considered and not used.
- Shadows are used only where something floats above the sheet: popovers, menus, the colour picker, modals, the inline editor and the document page.
- Menus open below their control (above when there is no room) and line up with the edge nearest the window side the control sits on: in the properties panel and the Export popover, the menu's right edge meets the control's right edge and the menu grows left; elsewhere the left edges meet.
- Elevation goes paper → sheet → sheet-raised.

## Typography
The UI uses only two families: sans and mono. The serif (`--font-tex`, KaTeX_Main) is kept for content: text on the canvas (`.tx`) and the typeset document page (`.doc-page`). Never use it for UI chrome.
- **UI:** Inter Display at 13px, served from `public/fonts/`. The normal weight is Medium: one `@font-face` maps 400 and 500 to `InterDisplay-Medium.woff2`; 600 and 700 are SemiBold and Bold, plus an italic. Medium and SemiBold are preloaded, and all are precached by `sw.js` so the chrome looks the same on every platform; system-ui is only the fallback while it loads. Labels are 12px in graphite.
- **Section titles** (`.sec-title`, `.pop-title`, `.panel-head span`, `.sc`): 11px, weight 600, sentence case, in pencil.
- **Type scale:** 10 (rulers, captions) · 11 · 12 · 13 (body) · 15 (titles). Nothing below 10px (HIG macOS minimum).
- **Labels:** buttons, menu items and dialog titles use title-style capitalisation; checkbox labels and hints use sentence case. On macOS, shortcuts show as glyphs in the order ⌥⇧⌘.
- **Numbers:** ui-monospace with tabular-nums for numeric inputs, the status line, rulers and the doc HUD.

## Spacing and measurements
- 4px base.
- Top bar 44px with 28px controls (8px above and below); toolbar groups are separated by space, not rules; one prominent action (TikZ).
- Tool rail 48px with 32px rounded buttons; a tool group (the buttons with a corner mark) opens its flyout when the mouse rests on it for 120ms and closes it 280ms after the mouse leaves both button and flyout, so the 6px gap can be crossed; moving to another group's button switches at once, and its tip doesn't show while the flyout does. A click keeps the flyout open until a choice, a click elsewhere, Escape or a second click; touch and pen still tap. document list 200px with inset 28px rows (each with a 14px line icon for its kind: a Classic document is an outlined page whose top-right corner is cut diagonally with a square-drawn fold, never a filled page), which the top-bar toggle folds open and shut in 240ms (its rows clipped, not rewrapped, and the drawing held still on screen, same place and scale, so the list only covers or uncovers its left side; instant under reduced motion); properties panel 280px (`--props-w`) with 12×16 section padding and an 84px label column. The panel is a floating window (12px corners, pop shadow) 8px in from the top right of the canvas, below the ruler and above the status bar, so the canvas runs the full width beneath it; its first heading (which names what is selected) is lifted out of the scrolling part into the window's head, so the scroll bar starts below it; the whole head is clickable (pointer cursor) and folds the window up to that heading or back down, easing its height over 240ms, with a chevron at its right (∧ open, ∨ folded) as the keyboard and screen-reader control. Folded or open is remembered. Stacked full-width buttons in it are 8px apart.
- Panel headers 40px; rulers 18px; status line 24px.
- Every control is `--ctl` 28px (HIG macOS default); dense secondary controls are `--ctl-sm` 24px (HIG minimum 20). Context-menu rows 26px, inset 5px.
- As the window narrows the toolbar sheds the wordmark (≤1360), segment icons (≤1240) and button icons (≤1140).

## Selection language
- **Marquee**: drag left-to-right for a window selection (shapes wholly inside; red-pen dashed box). Drag right-to-left for a crossing selection (anything whose drawn outline or fill the box touches, not just its bounding box), shown in highlighter yellow (`--marker`).
- **Selection box:** red pencil, 1px, dashed 4/3.
- **Group box:** red, dotted 1/3.
- **Main handles:** 7.5px squares with a white fill and red stroke.
- **Control points** (curves, plots, CD arrows): blue circles.
- **Marquee:** red wash with a dashed edge.

## Status line (`#status`)
- Zoom in the status bar: − [field] + 1:1 Fit. The percentage is a text field: click selects it, type a number (with or without %), Enter or leaving applies, Esc reverts; values clamp to 10–800%. 1:1 is the dedicated reset to 100%.
- Grid spacing is the same kind of field (`grid [0.25] cm · snap on`): 0.05–5 cm, an app preference saved with snap. Minor lines follow it; major lines stay on whole centimetres when the spacing divides 1 cm, else every 4th line.
- Groups (position · selection · grid/snap | pages | zoom) are separated by empty space in `--gutter`, a step deeper than the bar, so the groups read as separate pieces. The gap before zoom only shows with the page navigator.
Shows the cursor as `x · y cm`, the selection as N selected with its width × height in cm, and the grid size and snap state. Zoom controls −, %, + and Fit sit on the right.

## Page mode
- The sheet is `--sheet-raised` (white) on the `--paper` desk with a faint offset shadow (ink at 10%); the grid drops to 55% opacity.
- Margins are `--bluepen` dashed 4/3 at 35% opacity: construction lines, like the other blue guides. They hide with the grid.
- Content outside the paper is covered by a desk-coloured mask at 72%, so it reads as "off the page" without disappearing.
- Page numbers sit outside the top-right corner in mono, in pencil.

## Whiteboard mode (`kind: 'board'`, `body.mode-board`)
- One diagram on an endless canvas, stored like a Classic file with a single block, so drawing, undo, TikZ, export and import are the Classic diagram's. No Diagram/Document switch, no block selector.
- Quieter chrome for an infinite surface: no rulers or ruler corner, no origin axes, and a dot grid (`#gridDots`, `--faint` dots 1.2px on screen) in place of the line grid. Dots sit on major grid lines (≈1 cm) and double their spacing until they are at least 18px apart, so zooming out never turns the board grey. Snapping still follows the grid setting.
- Zoom reaches down to 3% (other modes stop at 10%). Wheel / two-finger scroll pans, pinch or Ctrl+wheel zooms, as elsewhere.
- A Hand tool (`H`, `.hand-only`, grab / grabbing cursors) sits under Select in the tool rail; it shows on whiteboards and Page files (`hasHand` in app.js) and falls back to Select when leaving them.
- The empty hint, sidebar title ("Whiteboards"), New tooltip, export heading and Export/TikZ button tips say "whiteboard".
- The empty hint (`#emptyHint`) is centred in the canvas left of the floating panel (`left: calc((100% - var(--props-w) - 16px) / 2)`), and never wider than that free area.
- The status hint (`#hint`, ink pill under the ruler) is centred the same way and keeps its line breaks (`white-space: pre-line`), so a second sentence can sit on its own line. ⌘S without the File System Access API (Safari, Firefox) adds a second line: "Remember to occasionally save to file to prevent accidental losses."

## Colour fields
- Every colour choice is the same control: a swatch button (`.cbtn`), the colour's name beside it (`.cval`), and the shared colour picker (`TD.openColorPicker`) on click. No swatch dropdowns and no native `<input type="color">`, in the main panel, the block editors and the document toolbar alike.
- In LaTeX blocks the picker runs in tex mode (`TD.texColor.field`): its presets are xcolor names (red … violet, their !20 tints, magenta … white) and "Change Preset Colors" is hidden. A preset is written by name, anything else as `rgb,255:red,R;green,G;blue,B` (braced inside key=value lists); the document toolbar writes `\textcolor[HTML]{…}` for those.
- A field that can be left unset says what unset means: Default (the ink), None (no fill) or Same. The picker's unset button carries the same word (`noneLabel`; Default in tex mode, No Color only in the main panel's own picker). Only things that can draw a colour get a colour field (quantikz sticks, `\push` and `\makeebit` get none).
- Where each block puts its colour fields: Quantum (a gate's Fill and Line, other elements' Colour; a group's Fill and Line, a fill adding `background`; a slice's Colour), State machine (a state's Fill, Line and Text; a transition's Colour and Label colour), 3D geometry (Colour and Fill), Bit field (a field's Fill → `bgcolor`), Timing (a data cell's Fill plus a Solid | Hatched switch), Bloch (the panel's colours), tikz-cd / xymatrix (objects and arrows), and the document toolbar (text colour → `\textcolor`, highlight → `\colorbox`; the glyph shows the last colour, and the selection is wrapped when the picker closes). A new block or editor gets its colours the same way.
- Where a block has a free Options field, the colour keys a picker owns (`fill=`, `draw=`, `text=`, `color=`) leave it, so nothing is written twice.

## Fill picker
- The colour picker gains Basic / Gradient / Pattern tabs only for fills. The active tab is ink text with a 2px ink underline (no accent colour).
- Gradient stops are small pentagon markers under the bar; the selected one is red pencil.
- The width and dash dropdowns preview the actual stroke at real width, with the px value and its pt equivalent in mono.

## Status
- Saving is continuous. "Autosave enabled" (`#saveState`, 11px pencil grey) sits right of the file name in the top bar; only a failure changes it (red SemiBold text plus a one-off hint). Below 1700px, where the top bar has no room to spare, it hides while saving works and reads "Not saved" when it fails (the full message is its tooltip). It stays on one line and ellipsises rather than wrapping.
- The sidebar footer holds the GitLab mark at the left (14px, pencil grey, ink on hover, 20px hit area; links to the repository), then an open-book line icon (same size and colours) that opens the guide (`guide/`, a standalone page in the app's tokens and fonts, light and dark) in a new tab, and the version at the right, which links to that release's tag. The app asks no outside site for anything (no star count).
- The app version sits at the right of the same footer (`v1.1.0`, mono, same muted colour). Its single source is `TD.VERSION` at the top of `js/shapes.js`: bump it with each release tag. The page-layout LaTeX export header also carries it.
- A newer release on the same host: the build writes `dist/version.json` (`{"version":…}`, left out of the service worker's precache), and the app fetches it once per load (`cache: 'no-store'`, same origin, never an external link). When it is newer than `TD.VERSION`, the version gets a `--marker` dot (as on a linked file with unsaved changes) that pulses twice, the title "DiagramTeX X is out (this is Y): click to reload", and a click reloads. No answer (dev, offline) changes nothing.

## Text
- Text tool: a click places a line of text; a drag (at least 12 screen px each way) draws a paragraph box. A box has a fixed frame (`tw` × `th`), text wraps at its width from the top, eight handles resize it, and overflow runs on below the frame instead of being hidden. In a box, Enter is a new line and ⌘↩ or Esc finishes.
- The inline text editor opens roomy: 360px wide (or the paragraph frame's on-screen width, up to 640px), at least three lines tall, 14px mono. It grows with the text up to 260px, then scrolls, and stays inside the canvas.

- Align applies to all text: a segmented control of four heavy-bar icons (Left, Centre, Right, Justify), 30px segments, stroke 2 with butt caps. Justify is shown but disabled until the text has a wrap width. Point text defaults to Centre, paragraph boxes to Left; TikZ gets `align=…` on multi-line nodes.
- Vertical (`valign`: top, middle, bottom) is a second segmented control under Align, three icons: a rule at the held edge with an arrow towards it (arrows both ways for middle). Point text keeps (x, y) as its centre; `TD.textHold` moves the centre when the box's height changes (typing, size, font, maths style, wrap width) so the chosen edge stays put, along the rotated axis if rotated. Switching Vertical never moves the text. New text is top; old text without `valign` stays middle. In a paragraph box it places the text inside the frame (default top). Multi-line or wrapping top and bottom text exports with `anchor=north`/`south` at that edge.

## Cursors
- Use the standard CSS cursor for what a drag will do. Never `pointer` (the hand) on canvas handles: the hand is for links and buttons.
- Edge and corner handles resize: `ew-`, `ns-`, `nesw-` or `nwse-resize`, turned with the shape's rotation and snapped to the nearest of the four. Text wrap and circle radius handles count as edges.
- Point handles (line ends, vertices, arc ends, arc centre) and shape bodies: `move`. Space held: `grab`; while panning: `grabbing`. Rotation zone: the custom rotate cursor. A single block whose content never turns (plot, CD, chemfig, timing, the 3D figures…, `FIXED` in app.js) gets no rotate zone, no Rotate menu item and no "rotate, flip" in the panel hint; Ctrl+R does nothing. Two or more selected objects can still be turned about their centre. The zone is a small tab straight out from the middle of each edge (28px wide centred on the edge's midpoint, narrower on a short edge; 9–26px out along the outward normal). A strip along the whole edge was tried and felt too greedy, as was a radial zone around the corners. It stays 9px clear of the resize handles the shape actually has, so a near miss on a handle still resizes, and it never covers another shape: pressing on another shape selects it.
- During a handle drag the canvas keeps the handle's cursor, so it doesn't flicker when the pointer outruns the handle.

## Installable app (PWA)
- `public/manifest.webmanifest` (standalone, cream background) and `public/sw.js` make the site installable: Chrome/Edge show an Install button in the address bar, Safari uses File › Add to Dock (iOS: Share › Add to Home Screen).
- `sw.js` precaches every same-origin file, so the app works offline from the first visit. Fetches go network first, falling back to the cache when offline or after 4s, so a deploy shows on the next load. Cross-origin requests pass through. Bump `CACHE` in `sw.js` with each release. The deploy build (`scripts/build.js`) joins the scripts into `js/bundle.js` and the stylesheets into `css/app.css`, and rewrites the precache list from `dist/`, so a first visit makes about 60 requests instead of 177. The hand-kept list in `public/sw.js` only matters when testing offline locally.
- Icon (`public/icons/`): engineering-paper grid, a ball-shaded charge and an ink arrow. `icon.svg` is the rounded tile (favicon and "any"); `icon-maskable.svg` is full-bleed with the art in the safe zone. PNGs are rendered from these at 32, 180, 192 and 512.
- `theme-color` follows the appearance (#fffdf8 light, #242320 dark), so the installed window's title bar matches the top bar.

## Phones (`#phoneWall`)
- A narrow upright screen (`max-width: 599px` and portrait) gets a full-screen notice instead of the editor: the app icon, "DiagramTeX needs a bigger screen" (22px/600, balanced), a line pointing to a computer or tablet with the URL in ink, and a muted note that files stay in that browser. `--paper` ground, everything else hidden. It has no close control. Landscape phones, iPhone Duo opened flat and tablets are not affected.

## Rendering at scale (`render()` in app.js)
- A shape's markup does not depend on the view: hit outlines take their width from `--hitw` (14 screen px, set in `applyView`). Pan and zoom call `renderView()`, which only moves the view.
- Markup is remembered per shape against its JSON (`drawn`); only shapes whose markup changed are put back into `#content` (`paintContent`). Lines that hop over others are always redrawn. Fill defs live in `#contentDefs`.
- Over 400 shapes, only those within one view's width and height of the view are in the canvas (`paint`); leaving that margin, or zooming in 3×, paints again. Selection outlines off screen are skipped too.
- Text sizes are measured in one layout pass per render (`TD.measureBatch`): measuring one at a time forced a layout of the whole canvas each time.
- `byId` keeps an id index; snapping while dragging uses a grid of the other shapes' anchors.
- Dragging more than 200 shapes (`FAST_DRAG`) leaves them untouched until the drop: their painted elements get the class `mv` and slide by `--mx` / `--my` on `#content`, `#overlay` slides by a transform, and only connectors attached from outside are redrawn (`fastMove`, `fastLinks`). The selection snaps by its bounding box's corners, edge middles and centre. On release each shape is translated once (`endFastMove`).
- Undo steps hold only what changed (`commit`): changed, added and removed shapes as JSON before and after with their list positions, the whole id order only when shapes were reordered, and a Page file's page count. `base` keeps the drawing as of the last step as JSON per shape, so `begin()` costs nothing. Undo keeps 300 steps or about 40 MB of text, whichever is less (at least 5).
- Files and the file list (`diagramtex.doc.*`, `diagramtex.index`) live in IndexedDB (`js/storage.js`, database `diagramtex`, store `kv`), read into memory at start so the app reads them synchronously; writes are batched into one transaction and broadcast to other tabs. `init()` waits for it and the loading screen waits for `TD.ready`. Files found in localStorage move in at start. Without IndexedDB everything stays in localStorage. A write that fails is shown in `#saveState`.
- Browser storage keys and the file signature are `diagramtex` (`app: 'diagramtex'`, `% diagramtex-data:`). An inline script in `index.html` moves `texdiagram.*` keys to `diagramtex.*` once; the importer reads both comment names.

## Files sidebar
- Right-click a file: Open (if not the open one), Rename…, Duplicate, Save As…; Copy, Paste; Download (.json); Export ▸ LaTeX, TikZ (Classic), HTML, Image, Print; Delete. Rename/Duplicate/Save As/Copy/Paste/Delete work on that file in place; Download/Export/Print open it first, since they act on the open file.
- Rename… turns the row's name into a field in place (Enter or clicking away keeps it, Esc cancels); the file isn't opened, and the top-bar name follows when it is the open file. With the sidebar hidden it falls back to the top-bar name field.
- Right-click the empty list area: New, Open File…, Paste.
- Copy puts the project JSON (same as Download) on the system clipboard; Paste opens it as a new file and never reuses an existing name ("… copy", "… copy 2").

## Layers (`#layersWin`, the layers block in app.js)
- `#rightCol` holds `#propsWin` at the top and `#layersWin` pinned to the bottom (`margin-top: auto`, so it never moves with Properties), at least 8px apart; layers caps at 30% of the column (when Properties is folded it fills the rest, 50px below Properties' header, however few rows), hidden in document mode and print.
- Rows are 32px: eye, 28×22 thumbnail on `--canvas` (the shape's export SVG, non-scaling stroke), name, lock (shown on hover or when set). Selected rows use the selection tint; hidden rows dim; group members indent.
- Shape fields: `name` (a layer's own name), `gname` (a group's name, on every member), `hidden` (not painted, not in TikZ/export), `locked` (painted with class `locked`, no pointer events). Hidden/locked shapes drop out of the selection (`pruneSel`).
- Drop marks: a bluepen line above/below, or a tinted row for "into" (lower half of an open group). Hovering a row draws a dashed `--bluepen` box (`.layer-hover`) on the canvas.
- Panel open/closed is saved in prefs (`layers`).
- Folding either window goes through `foldWin()`: both windows ease their height together (.24s, `cubic-bezier(.3, .7, .2, 1)`), since Layers' cap depends on Properties being folded. `.folding` keeps contents shown and lifts the Layers cap while moving; a list that scrolls before or after keeps its scroll bar throughout, and only one that fits at both ends gets `.fold-clip` (overflow hidden). Reduced motion skips it.

## Dialogs (`js/dialog.js`)
- Never use the browser's `alert` / `confirm` / `prompt`. Use `TD.confirm(title, message, opts)`, `TD.prompt(title, value, opts)`, `TD.alert(title, message)`; each returns a Promise.
- The title asks the question ("Delete "Name"?"); the message says what happens. Buttons name the action ("Delete", "Save", "Add Link"), never "OK" when a verb fits.
- Destructive actions pass `danger: true`: red button, focus starts on Cancel, so a stray Return can't delete.
- Esc cancels, Enter takes the default, Tab stays inside, focus returns to where it was. One dialog at a time.
- Buttons sit the same distance (`--tdd-inset`, 14px) from the right and bottom edges, and the sheet's corner is concentric with theirs: radius = button radius + inset (6 + 14 = 20px). Text keeps its 20px inset.

## Kept TikZ code and LaTeX checks (`js/rawtikz.js`, `js/texlint.js`)
- A statement the importer can't model is a `tikz` object: its preview drawn as usual, inside a dashed `--graphite` frame (0.8px, 3/2 dashes) with a 10px mono tag above its top-left corner naming the first command (`\foreach`, `axis`…). Frame and tag keep their screen size: the canvas svg carries `--zoom` (set in `applyView` next to `--hitw`) and the CSS divides by it. Never pass the zoom into the markup.
- The import dialog's head holds a `.seg#impHow` switch, **As Written** | **Editable Shapes**, between the title and the file buttons, remembered in `diagramtex.importHow`. Either way each imported picture is one group (one `g`), and Insert into Diagram (the primary button, last before Close) places it centred in `fitArea()` (the canvas left of the panel column) on whole grid steps, like paste. In the Document view, Insert and ⌘V (TikZ or copied shapes) add new blocks after the active diagram (`insertBlocks`), make the first new diagram active and scroll to it, without leaving the view. Editable Shapes replaces each kept statement with its preview shapes (`TD.importLatex(src, { editable: true })`), and the report line says "converted to shapes as drawn" instead of "kept as TikZ code".
- Its panel: the code in an editable `textarea.code` (the preview follows), then `TD.lint` rows, then the importer's reasons as `.err` lines, then **Convert to Shapes** (`.wide`).
- `TD.lint(src, { libs, pkgs, preview })` returns `{ sev: 'error' | 'warn' | 'info', line, msg }`; `TD.lint.html(list, max)` renders `.lint` rows: errors and warnings in `--redpen`, notes in `--graphite`, the line number in mono. No icons, no new colours.
- Where the rows show: the import dialog's message line (`#impMsg` gets `.report`, refreshed 300ms after typing stops), the TikZ/LaTeX code dialog's foot (`#tikzLint`, warnings and errors only), the TikZ code panel. A `.modal-foot.report` lists line · code · reason in a three-column grid, scrolling past 168px; nothing in the dialog moves when it fills.

- Named points: `\coordinate (A)` is a `coord` object (`tikzName`), drawn as a `--bluepen` construction cross (8 screen px) with its name in 10px mono up and to the right, both at screen size (`--zoom`); not exported as ink; lines tied to it are written with `(A)`.

## Code view (`#tikzOut`, the TikZ/LaTeX code dialog)

## Attached connectors
- Lines, arrows, curves and springs attach an end that is dropped on a shape's outline or one of its snap points. The end is stored as a position in the shape's frame (`link1` / `link2` = `{ id, u, v }`) and follows the shape when it moves, resizes or rotates.

- Copies keep links only to shapes copied with them. TikZ export uses plain coordinates.

- Read and drawn too (chemfig 1.8, `chemfig.tex` 2026/09/19): `\definesubmol{name}<n>[alt]{code}` (`#1`… replaced, alt code when arriving from the left), `!{name}{args}`/`!x`/`!0`, expanded at layout time and marked `.sub` (the editor won't pick them); `%` comments and the line breaks after `\definesubmol`/`\setchemfig` (one 3.333pt space each before a scheme); `|` splits atoms; `fixed length` (next node at the departure atom's border + L, arrival anchored at 180+angle); `@{name}`/`@{name,pos}` on atoms and bonds; scheme arrows `(.a1--.a2)` via TikZ anchors (`mid` = base+0.5ex); `\hreac[kv] … \endhreac` (centred on a `\vphantom{A}`, hreac sep 0.5em, arrows max(3em·coeff, label+2·3pt), drawn full length); `\chemmove` TikZ paths (overlay, not in the box; curves shortened as pgf does by default: only the ends move). `\charge` marks are overlay (not in the box), `\Charge` counts.
- Export: `\usepackage{chemfig}`, the code unchanged in `\node[anchor=north west, inner sep=0pt]` at the drawing's top left; a colour other than black adds `text=` (bonds follow it).

## Chemistry editor (`js/cfeditor.js`)
- Same shell as the Feynman editor (`#cfModal`, `cz-*` classes, `.qe-item` palette tiles drawn by `TD.chemMini`), with a grid for the eye only: chemfig has no coordinates, so nothing snaps to it. The side pane's code wraps (chemfig lines run long).
- Palette: Atoms, Bonds, Rings, Groups, Charges, Reactions. An item acts on the picked atom or bond (relabel, grow a bond in the free direction, attach a ring or group by a bond, fuse a ring onto a ring's side, add a charge at a free spot, retype a bond); with nothing picked it is armed until Esc; Reactions act on the whole drawing (wrap in a scheme, add arrow + copy of the molecule, or `\+` + copy). Bond kinds set the kind new bonds get (`.on`). Keys: `C H N O S P F I` relabel the picked atom, `1 2 3` bond kinds.
- Stage: hover rings an atom (`.fy-vhov`) or tints a bond (`.cf-bhov`); selection is the red-pen ring or `.ze-wsel` halo. The picked atom's `.ze-knob` sits in its free direction (zigzag off a lone bond, else the widest gap); dragging it draws a dashed blue draft snapped to 15° (⌥ free), clicking it adds the bond there. Dragging an atom turns and stretches its incoming bond (angle snapped, length in quarters). A new bond goes straight on at the chain's end, else into a branch; an angle equal to the default is not written. The view only moves when a new piece leaves it (pans, or fits if it no longer fits).
- Deleting: an atom or bond cuts its chain from there on (an emptied branch or molecule goes too); anything in a ring deletes the ring. Right-click menus put Delete last with the trash icon, red on hover.
- Side pane: atom (Label, Charge None/+/−, Lone pairs ↑ → ↓ ←, Delete), bond (Type, Angle, Length, Options; Angle and Length disabled and tinted in rings), arrow (Type, Above, Below, Angle, Length, Delete Arrow); in a scheme a Molecule section (Name, Delete Molecule). Code: written back only after an edit; typing is read back after 250ms, each pause one undo step.

## Commutative diagrams (`js/cd.js`)
- Blocks → CD. The object *is* its `tikz-cd` source, drawn as vectors and edited in the CD editor (`js/cdeditor.js`). Diagrams from the old grid editor (type `cd` with an `arrows` list) are brought up to a CD block on load. Placing it only selects it; double-click, Enter, Edit or the panel's Edit Diagram… open it; Done is one undo step.
- Sizing follows pdflatex, measured against compiled output: labels at 0.68 of the text height, each cell's height its content's minus the slack of an `A` plus 1.7ex, row centres shifted by tikz-cd's −0.92pt cell offset (carried on each node as `oy`). A test diagram comes out 56.3pt tall against LaTeX's 55.5pt.
- Export: `\usepackage{tikz-cd}`, plus `decorations.pathmorphing` when an arrow is squiggly; the code unchanged in a `\node` inside `\pgfinterruptpicture`.
- quiver output (`cd.js`): ends `from=r-c`/`to=r-c`, relative `from=ul`, or a label `name` (resolved in passes, so 2-cells may point at 2-cells); `curve={height,pos}` follows quiver.sty (controls at pos and 1−pos, offset to the right of travel); `between={a}{b}` trims the drawn arrow while labels sit on the whole curve; `nfold`, `tail reversed`, `2tail`, `no body`, `loop/in/out/distance`; label `anchor=center` is a description label, `rotate=` turns it, `text=…background color` paints it in paper. xcolor expressions (`rgb,255:red,…`) are resolved by `TD.xcolorExpr` for arrows, labels and KaTeX `\textcolor`. The CD editor's `load()` moves position-written arrows into their source cell as relative dirs; named ones stay in the last cell.
- Blocks → XyMatrix (`js/xy.js`, type `xy`). The object *is* its `\xymatrix{…}` source. It is read into tikz-cd code (`TD.xy.toCd`; anything without a counterpart rides along in `xy …` options) and laid out by cd.js with xy's profile: 2pc separations edge to edge, 3pt object margins, labels 2.5pt off the arrow, `.5ex` shifts, xy's two-stroke tip, `@/^/` curves .5pc deep. The CD editor opens it in xy mode (title XyMatrix, code head "xymatrix", Crossing, bend Angle and the Options fields hidden, separations in pc); it writes back with `TD.xy.fromCd`. Export: `\usepackage[all]{xy}`, the code unchanged in a node, centred on xy's own box (entries, straight arrows and labels; curved arrows stick out of it).
- CD ↔ XyMatrix conversion: the CD panel's last action is Convert to xymatrix, the XyMatrix panel's is Convert to tikz-cd (plain `.wide` buttons under Copy … Code). `TD.xy.switchType` changes `s.type` and `s.src` in one undo step and keeps the block's centre. It stores `s.conv = { from, src, out }`; converting back while the code is still `out` restores `src` exactly (hint "Restored the original code"). Approximations come back as warnings, shown in the hint for 5s (a panel action may return `{ text, ms }`). The Blocks flyout's title and button tooltip say "Blocks (experimental)"; the flyout title adds a second line in `--redpen` (`.pop-warn`, weight 500): "Some inputs might not be rendered correctly.".

## CD editor (`js/cdeditor.js`)
- The ZX editor's frame: palette of objects and arrow styles on the left, the grid in the middle, properties and the live code on the right. Typing on a selected cell edits it; dragging from cell to cell draws an arrow in the palette's style; Alt-drag copies a cell.
- Only cells that change are rewritten, so hand-written code keeps its form.
- Arrow panel: an arrow's style is two independent choices, its head (the pictures, `TD.CD_HEADS` names) and its line (Solid / Dashed / Dotted / Squiggly, one switch); picking one never clears the other. Crossing is its own switch (None / Gap). Side and At are disabled until the label has text, and emptying the label drops it from the code. Rows of independent toggles (`.ze-flags`, as in ZX's Line row) get no sliding knob: each button draws its own, since several can be on.

## Grid editors, shared (Quantum, ZX, CD)
- **One bin.** Every delete icon (toolbars, layers, menus, editor gutters, table rows) is the same drawing, `M4 5.5h12M8 5.5V3.5h4v2M5.5 5.5l1 12h7l1-12` in a 20-unit box at stroke 1.5; smaller placements (the 12px gutter bin) thicken the stroke so it lands near 1.2px. Red pen only where the click deletes right away (gutter bin armed, a table row's bin).
- **Delete gutters** (`TD.gridDel` in qceditor.js): a 22px band left of the rows and above the columns. While the pointer is anywhere in a row or column (a cell, or the gutter beside it, including the space around a bin), that line's bin shows faint grey (`TD.gridDel.near`). Only the round bin itself is live: pointing at it marks the whole line in a dashed red-pen wash and turns the bin red, and a click deletes the line as one undo step. A click beside the bin does nothing. No gutter while dragging or placing.
- **Live panels:** panels re-render through `TD.morph` (shapes.js), which patches the DOM in place, so the field being typed in keeps focus, caret and value while every other field takes its new value. Focus handlers ignore the moves (`TD.morph.busy`). Nodes added by other scripts (a switch's `.seg-thumb`, the `has-thumb` class) are left alone, so switches still slide.

## Bloch spheres (`js/bloch.js`)
- Blocks → Bloch. The object *is* its `blochsphere` source, drawn with the package's projection, circle planes split into back and front halves, shaded ball and dotted state vectors. There is no overlay editor: the panel is the editor.
- Panel: Radius (cm); Tilt (−90…90) and Rotation (−180…180) as sliders whose degree value is an inline field (borderless until hover, blue focus ring, like the document name); Ball as a text switch (Shaded / Outline / None) whose segments share the row. **States** is a grid table (label, θ, φ, a red-pen bin): a label writes or removes the state's `\node … {$…$}`, θ/φ rewrite it as `\drawStatePolar`, the bin removes the state and its label. **Colours** are colour fields (not unsettable): the ball's `color`, states → `statecolor`, labels → each `\node`. Then the editable code.

## Electrical circuits (`js/circuit.js`, `js/czeditor.js`)

A file from before has no wavelength, so one period fills the width as it used to. Insert → Circuit does the same.

- The rail's Physics flyout (pendulum icon, between Electrical and Misc) holds two `pop-title` sections, Mechanics (`cat: 'mech'`) and Optics (`cat: 'optics'`). Physics objects are px-parametric symbols: hatching (7px spacing, 45°), axles, bobs and angle marks keep their size when the box is resized. Mirrors and walls face left (hatching on the back, right side), as light comes from the left. Their menu icons are drawn at a compact `icon` size, not the placed size, so hatching and lens shapes stay readable at 34×24.
- Segmented controls in the editors' side panes (`.cz-props .seg-ctl`) get the `--wash` hover with `--ink` text, as on the main page.
- Circuit and quantum editor tool rows (`.cz-tools`) follow the main tool rail: 32px buttons 4px apart, 18px icons, graphite at rest, `--wash` on hover, `--ink` fill with a `--sheet` icon when active, 20px separators with 6px of air each side.
- Editor side panels (`.cz-props`) follow `#props`: 84px labels, 8px between controls, no margin above the first row or below the last; the first section's title names the item (13px/600 ink, like `#props h3`), later section titles are subsections (11px/600 pencil).

## Tooltips (`js/tooltip.js`)
- The app draws its own tooltips; the browser's never show. Every `title` attribute, including ones added or changed later, moves to `data-tip` (a MutationObserver); icon-only controls and fields get it as their `aria-label`, others as `aria-description`.
- `.td-tip`: `--ink` fill, `--sheet` text, 12px/500 UI type, `--r-sm` corners, `--shadow-pop`, max 280px wide, 6px below the control (above it near the bottom edge), kept 8px inside the window, z-index 3000.
- Shows after 800 ms of hover; moving straight to another control shows its tip at once (within 400 ms). Pressing, typing, scrolling or leaving hides it; keyboard focus (`:focus-visible`) shows it too. Touch never shows one.
- On a Mac, shortcuts in titles are rewritten as glyphs when they become tips (`TD.macKeys`): Ctrl+Shift+Z → ⇧⌘Z, Ctrl+Enter → ⌘↩, Ctrl+scroll → ⌘-scroll; Shift on its own ("Shift+drag") stays in words. Titles are written the Windows way, once.
- A shortcut in brackets is set apart as a key hint: “Undo (⌘Z)” ends with a muted ⌘Z; “Wire (W): drag between points…” puts “Wire W” on the first line and the description muted under it.
- The circuit block (`cz`) is a list of circuitikz items in local cm (y up), drawn on the canvas with the same renderer as the editor. Leads are wire weight (0.4pt), part bodies twice that. Double-click, Enter or the panel's Edit Circuit… opens the editor.
- Generated parts (`js/czparts-gen.js`, 149 parts, loaded after the hand-drawn part files): made by `scripts/cz-extract.py`, which compiles each part with circuitikz (latex + dvisvgm), reads the SVG back into cm paths (fills as ink/paper/grey, pgf clips cut to their region, leads removed, `w` from the gap between them) and the anchors from TeX (one pin name per point, aliases dropped). Never hand-edit the file; change the script's `SPEC` and rerun it (`python3 scripts/cz-extract.py -j 10`). Keys come from the tikz name; `KEY_FIX` renames the ones a hand-drawn part already uses (a duplicate key throws and stops the rest of that file). Parity: `czg_*` scenes, one per family. Category `tube` (Tubes) is new.
- The editor is a large overlay modal (`#czModal`, 1600×900 max, 97vw × 93vh): a header with tool buttons (select, wire, rotate, flip, delete, undo, redo, fit), Cancel and Done (primary); below, palette 240px | paper-coloured stage on a 0.25cm grid | side pane 400px (200 / 300 under 1100px; one column with the palette hidden under 800px). The side pane stacks the selection's properties (hidden when nothing is selected, at most 55% high) over the code: a head with “circuitikz”, the count “n parts · m wires” and Copy, then a mono textarea on `--well` (on focus `--sheet-raised` with a 2px bluepen bar on the left). The drawing rewrites the code unless the textarea has focus; typing is read back 250ms after the last key and on blur, as one undo step. There are no Draw/Code tabs. The stage is paper, like the page, so parts read as ink on paper in both themes.
- Palette: search field on top, then **Recently used** (the last 12 parts placed) and **Common** (24 everyday parts), then the categories, all as `<details>`. Only Recently used and Common start open; every other section stays shut until the person opens it, and each section's open or shut state is remembered in the browser (`diagramtex.cz.open`, `diagramtex.cz.recent`), so rebuilding the list never opens anything on its own. Click to arm a part, or drag it onto the stage.
- Its shortcuts are captured while it is open (V, W, R, F, Delete, ⌘Z/⇧⌘Z, ⌘D, ⌘A, ⌘F or /, arrows, 0, Esc, ⌘Enter, ⌘S), so the main editor's stay off. ⌘S (Ctrl+S) writes the work back to the page as one undo step there and keeps the editor open, showing “Saved to the page” in the tip for 1.5 s; Esc afterwards closes without asking, as nothing is left to discard. The browser's Save Page never opens. Cancel with changes asks with the standard danger confirm (Discard).
