# DiagramTeX interface system: "drafting table"

## Intent
- **Who:** someone writing a paper, problem set or lecture notes who needs a figure in their LaTeX. They come from a `.tex` file and go back to one.
- **Task:** draw a precise figure and get clean TikZ out of it.
- **Feel:** a drafting table with engineering paper, ink and a red pencil. It should be quiet, exact and warm. It should not feel like a SaaS dashboard.

## Signature
**Centimetre rulers** run along the top and left edges of the canvas, in TikZ coordinates with y pointing up (`#rulerX`, `#rulerY`, drawn by `drawRulers()` in `src/application/app.ts`).
- The tick step adapts to zoom: 0.25 → 500 cm, with labels at least 56px apart. Steps of 1 or 2 cm get quarter subdivisions; steps of 5 get fifths.
- The selection's extent is shaded on both rulers in a red-pencil wash.
- Each ruler is drawn at its own element size (`preserveAspectRatio="none"`), and a ResizeObserver on `#canvas` re-renders when the stage changes size without the window (sidebar folding, leaving Table or Quick). The ruler SVG fills its axes independently: its 1px border leaves a 17px cross-axis viewport, so preserving the aspect ratio of an 18px viewBox would shrink the entire scale by 17/18 and move zero away from the canvas origin.
- A red hairline marks the cursor position.

**Logo:** "Node to Node", a coral round node and a blue square node joined by an indigo backslash edge (lavender `#F1EFFF` on dark). Kit, colours and rules live in `design/logo/` (`GUIDELINES.md`; early concepts in `concepts/`). In the app it appears in three places:
- **Top bar:** the mark (20px) followed by the outlined Inter Display Bold wordmark, at the left of the first row beside the centred file name; below 1361px only the mark shows. Language and appearance sit on the right. The second row holds the file actions and adjacent file-type and Classic Document/Diagram selectors. Entering the file-type selector expands its labels; the expansion persists across the gap and Classic views until the pointer leaves both selectors. Entering Document/Diagram directly keeps the file-type selector compact.
- **Loading screen:** an inline `#splash` in `src/index.html` paints the paper colour at once. The mark fades in only after 150ms, so fast loads never flash it; while it shows, the edge draws from the round node to the square, holds, then lifts off; it stays still under reduced motion. It's lifted on `load` plus fonts (at most 1.5s more), never later than 8s.
- **Icons:** favicon (small cut, edge lightens in dark tab bars) and the app icon (indigo tile).

**Colour restraint:** apart from user content and the logo, the only colour in the interface comes from the two pens. Active tools and menu highlights use ink, not an accent hue. Segmented controls are a recessed track with a raised selected segment; every track uses 3px padding and a 3px gap between segments (2px felt cramped, 4px looked worse). The raised segment is one knob per switch (`src/ui/services/segthumb.ts`) that slides to the new choice in 220ms (eased out, width and height following), so a switch reads as one control rather than buttons lighting up; a switch rebuilt by the click that changed it (properties panel, export menu) starts its knob where the old one was. The knob appears in place on first sight and when a hidden switch shows again, and is still under reduced motion.

## Interface kit (`src/ui/kit`, `css/kit.css`, `/kit.html` in development)
The app's controls as Svelte components, so a control is defined once and every place that shows it changes
together. Each component maps its props to the global classes in `css/kit.css`, which code that still builds
HTML strings uses too; nothing in the kit has scoped styles, because both kinds of code must draw the same thing.
- **Icon** (`icons.ts`): one drawing per meaning, by name, in a 20-unit box with a 1.5 stroke (`.f` parts filled);
  grid and tree icons are `qe-ic` outline/solid drawings at 1px. The tree icons keep their `.fe-turn` group so the
  tree editor can turn them with the tree.
- **Button**: outlined by default; `primary` (ink) for the one main action; `flat` for toolbars. A leading icon is
  16px with a 6px gap and 10px left padding, as in the top bar. A disabled primary drops to the `--wash-strong`
  fill with `--faint` text and doesn't react to hover.
- **IconButton**: `--ctl` square (32px in a block editor's `.cz-tools`), flat, icon only, its `title` required (the
  tooltip and the name). `danger` turns the red pen on hover on every flat or icon button.
- **Press**: everything clicked shrinks while held (80ms, ease-out) and springs back on release (360ms,
  `--ease-spring`, a slight overshoot): every button, the kit's and hand-written ones alike (the tool rail, the top
  bar, the zoom bar, swatches; no class needed), switch segments, list rows (not while a button or field in the row
  is held), the Quick list's rows, `summary` heads, links, menu
  and select-menu rows (not a row that opens a submenu, nor a "coming soon" control); a panel head that folds its
  panel presses its fold button; selects (a drawn one with its drawing) and sliders to 95% (a slider about its thumb, so the thumb stays put);
  small controls further so it shows, a switch to 90% and a checkbox to 85% (also when its label is clicked).
  Fields typed into don't, nor the colour picker's hue and alpha sliders. Reduced motion keeps them still.
- **Size**: `size="sm"` is `--ctl-sm` (24px, 12px text, 10px padding; square when icon only), only for dense
  secondary controls.
- **Segmented**: the switch track (`.seg`, or `.seg-ctl` in a properties row): 3px padding and gap, 5px segment
  corners, one sliding knob (`segthumb.ts`). One-of switches are a `radiogroup` of `radio` buttons; `many`
  switches (`.ze-flags`) are `aria-pressed` toggles with no knob, each drawing its own; a toggled button fades
  between its off and on look (200ms, `--ease`), also when the panel rebuilds the switch. The knob slides and the
  fade runs under reduced motion too.
- **Fields**: `TextField`, `TexField` and `NumberField` are white inputs that follow the model through
  `liveValue`; TeX fields take the standard placeholders. `Select` keeps a native `<select>` that the app's menu
  draws. `Checkbox` wraps its label in `.chk`; `Switch` is the 28×16 on/off switch. `ColourButton` is the
  44px checkered swatch with its name in mono pencil. `Slider` is a range with a 48px mono readout.
- **Menu**: rows are data (`MenuEntry`): icon (or the empty 16px column), label, shortcut, a tick for a pick-one
  group (`menuitemradio`), danger, disabled; `'-'` rules (trimmed at the ends and never doubled) and small headings
  (`.ctx-head`, 11px/600 pencil); submenus placed beside their row by `positionMenu`. `openContextMenu()` floats
  one at a point or beside a control: kept on screen and scrolling inside when taller, focus taken and given back,
  closed by a pick, Esc, a click or wheel elsewhere, blur or resize, fading out (the pop-in backwards, 120ms) as it
  goes. Rows press like buttons (95% while held, springing back), except a row that opens a submenu. ↑ ↓ Home End move, → and ← open and close a
  submenu.
- **Select**: one control for every pick-one list, plain or drawn; there is no separate dropdown button. A native
  `<select>` stays underneath (value, input and change events, type-to-select) and `selectmenu.ts` draws the menu.
  An option can carry a drawing (60×10 in the menu; the current one's, 40×8, also sits in the closed control), a mono
  note, its own font, a colour swatch and a group (a section title). A font list is one list, never split into
  sections. `columns` lays drawings out as tiles 2px apart (arrow tips),
  with arrows moving across and down. `custom` adds a line at the foot for a typed value (a custom dash): ↓ past the
  last option reaches it, Enter applies, Esc or ↑ goes back; a value outside the options shows as the custom label.
  `attached` draws only the chevron (24px), joined to the field before it (width presets). The menu opens 4px below
  (above when there is no room), lines up on the right in the right half of the window, fades out like a menu, and
  its rows press.
- **Text popup**: `TextPopup` is the in-place editor over an item (double-click a label): a LaTeX field (mono 14px,
  highlighted, LaTeX autocomplete) or MathLive (one maths field per line and a key hint), as the Text input setting
  says. Kinds: a line (300px, 40–160px tall, Enter finishes, Shift+Enter a new line), a paragraph (360px, from
  120px) and code (520px, mono 13px, from 150px), where Enter is a new line and ⌘/Ctrl+Enter finishes. Esc and a
  click away finish too. Its top centre sits under the item, kept 8px inside the stage. It is a manual popover, so it
  draws in the browser's top layer over every pane and the tool rail, placed in window coordinates by `place()`
  (following scrolls, window resizes and its own size); it is never larger than the window less 8px each side, and
  resizing it past the stage moves it back inside the window. It fades in (140ms) and out (120ms, scale .97). Its CSS is in kit.css. It is the canvas's text editor (`roomy`: a line from 76px, 360px wide or
  a paragraph frame's width at the zoom, resizable by its corner, under the app's popovers; `startEdit` in
  src/application/app.ts) and every label popup (`TD.input.popup` wraps `openTextPopup`). `caret` places the caret (the
  maths tool's `$|$`), `start` picks MathLive's first mode (a label starts in maths).
- **MathLive's own pieces** (`src/ui/services/mathlive-theme.ts`, kit.css): every field's lines are white (no tint for
  the line being typed), with blue-pen caret and selection. Its menu (☰ or a right-click) is the app's menu: 4px
  padding, 28px rows with `--r` corners, `--well` when pointed at or chosen by keys, `--rule` lines between groups,
  shortcuts in pencil, "›" for a submenu, 12px corners, fading in. Its ☰ is a 28px flat graphite button with the
  app's line icon. These styles go into each field's shadow root, because page CSS can't reach the highlighted row.
  Its command suggestions (`\fr…`) are styled as the LaTeX autocomplete: a white card of 28px rows, the chosen one
  `--wash-strong`, with no pointer tip. They sit in the top layer while shown, over the text popup. Its on-screen
  keyboard button is hidden everywhere. Its Color and Background swatches are the app's swatches: 24px with 4px
  corners and a hairline edge, 4px apart in a 4-column grid, a blue-pen ring on the one pointed at. MathLive's grey
  tiles and 1.4× pop-out are not used.
- **Tooltip**: any `title` becomes the app's tooltip (`Tooltip`, drawn by the tooltip service through the one floating
  copy in `tip-layer.svelte.ts`): ink, 12px Medium, 4×8px padding, `--r-sm`, at most 280px wide, 6px below its control
  (above when there is no room), centred and kept 8px inside the window; it fades in (80ms). It shows after 800ms of
  hover (at once within 400ms of another hiding) or on keyboard focus, and a press hides it until the pointer leaves.
  A trailing "(shortcut)" is a `<kbd>` (Mac glyphs via `macKeys`); "Name (key): what it does" puts the description on
  a muted second line.
- **Names cut short**: any name the interface cuts with an ellipsis (a file, layer, menu row, tab;
  `text-overflow: ellipsis` or a line clamp) shows in full in the same tooltip when hovered, with no markup of its own
  (the tooltip service measures it). Hovering elsewhere in its row (an icon, the padding) finds it, when the row is
  at most 48px tall and holds only that one cut-short name. A control's own tip goes under the name as the muted
  line, unless it already says the name. The tip is wider for a name (up to 480px) and breaks it anywhere. A name that
  fits, a focused field and a dropdown show nothing extra. So a new list needs no `title` just to show a long name.
- **Popover**: a panel opened from a control (`Popover`, placed by `placePopover`). `below`: 6px under it, above when
  there is no room; in the right 40% of the window it lines up with the control's right edge and grows left, else
  left edges meet. `beside` (flyouts): 6px to its right, its top `inset` above the control's. Always 8px inside the
  window. Padding `inset` (4, 8 or 12px) all round and a corner of 8px more, so it is concentric with the controls in
  it. Esc or a press outside it (the control, a select menu, a context menu or the colour picker don't count) closes
  it; Esc gives focus back to the control, and goes no further. It fades in (140ms) and out (120ms, scale .97) from the
  corner it grows from. Code that builds its panel as a string opens it with `openPopover(anchor, { content })` (the
  Export panels: 12px inset, 264px wide, Quick's 240px).
- **Flyout**: a tool group's button (a 4px corner mark; `--wash-strong` while open) and its Popover beside it, 8px
  padding. Hovering opens it after 120ms; it closes 280ms after the mouse has left both button and panel; moving to
  another group's button switches at once. A click pins it until a pick, a click elsewhere, Esc or a second click.
  Touch and pen open it by tapping. Opened with Enter or Space, focus starts on its first choice.
  The rail's ten groups are Flyouts whose `panel` is built by the app (`#fly-*`, `#insertPop`, kept in a hidden
  `.fly-panels` while closed); a flyout opens with its content level with the button's top (`inset` 8px above it).
  The draw-mode menu beside the shapes flyout keeps it open while the pointer is on it (`holdFlyout`).
- **Panels**: `PanelSection` (`.sec`: title with a `Badge` count and an action, then rows), `FormRow` (84px label
  column, then `.ctl`; `column` stacks a wide control under its label, `unit` sets a value beside its unit) and `Help`
  (`help` 12px graphite, `hint` 11px pencil, `error` 12px red pen and announced). They draw the panels' own markup;
  `#props` and `.cz-props` style it.
- **Badge**: a count beside a title, 11px pencil (`faint` in a palette), mono-width digits, 6px from the title (a
  title row that spaces its children, such as a palette category or the code pane's head, sets the gap instead).
  Code that builds a list as a string uses `badgeHtml()` (`src/ui/kit/markup.ts`) for the same markup.
- **Soon**: `soon` on Button, IconButton and Tile shows a feature not built yet: 45%, a dashed `--rule-strong` edge,
  `aria-disabled`, out of the Tab order, clicks do nothing, no press. Never hidden.
- **EmptyState**: a quiet centred message (12px pencil, an optional 13px/600 title) where a list or view is empty:
  a block editor's palette with no match, the "/" search, the Layers list. String-built lists use `emptyStateHtml()`.
- **SearchField**: `type="search"`, its placeholder also its name; `--well` until focused, then white with the blue
  ring (the block editors' part search).
- **Tile**: a picture choice, a 40×30 drawing over an 11px name (a long one, as Thai runs, wraps to a second line and is then cut; the title holds it whole), 8px padding, `--rule` edge on `--sheet`; hover
  `--wash`; current: ink edge on `--wash-strong`. `TileGrid` lays them four across, 4px apart.
- **SplitButton**: a main action and a 24px arrow joined (the inner corners square); the arrow opens a menu or a
  popover from itself. `toolbar`: flat halves, the arrow 18px, and `on` fills both as one control.
- **ListRow**: a 28px row, icon and name (cut short with …), trailing content, actions (20px, pencil; red on hover if
  destructive) shown on hover or focus; selected: `--wash-strong`, ink, 600; indented 16px a level. Renamed in place
  (double-click or F2; Enter or leaving saves, Esc cancels) in a white field with a blue-pen edge.
- **Toolbar**: one line of `ToolbarGroup`s, a 1px `--rule` between groups (none beside a switch). It measures its own
  width: too narrow, labelled controls drop their icons; narrower still it scrolls with no bar (a mouse wheel too)
  and fades 32px at the side with more.
- **Palette** and **CodePane**: a block editor's side columns as described under Block editors, as components: the
  palette's search, foldable counted categories, rows, tiles or icon tiles and its EmptyState; the code pane's head
  (package, count, Copy), note, code and message line. Every block editor's palette is the kit Palette, drawn from
  data (`editorPalette()`, src/editors/editor-palette.svelte.ts): a search matches every word of the query; Esc
  clears it, then leaves it; Enter picks the first match; a palette's drawings share one scale (`fitMini`).
  **A palette item is never cut** (src/ui/kit/fit-item.ts, `npm run test:palette-fit`): once shown, a drawing that
  reaches past its own box (set glyphs, maths, edge strokes) gets a wider viewBox, refitted within fitMini's bounds;
  a name wraps onto as many lines as it needs (no ellipsis, no line clamp, lines tall enough for descenders in every
  engine), may use a tile's side padding, and a single word too wide for it gets smaller text, down to 10px, rather
  than breaking mid-word (browsers don't hyphenate reliably, and `text-wrap: balance` with `overflow-wrap: anywhere`
  splits words, so names use `break-word`). In a 2-column palette, list rows stack their drawing over their name;
  in the 1-column palette, category titles wrap.
- **EditorFrame**: every block editor's window, as one component: the head (icon, title, its tools, a spacer, Cancel
  and Done) over the palette, the stage and the side (properties over the code). Every editor opens at the same size,
  up to 1600×900 (97vw × 93vh), set once in kit.css (`.modal-box.cz-box`).
- **Dialog**: `TD.confirm` / `TD.prompt` / `TD.alert` draw the kit's `Dialog` (buttons from `Button`). It opens with the
  scrim fading in (140ms) and the sheet popping in (160ms, from 97%), and closes the same way backwards. The answer and
  the focus come back at once; while it fades it is `.td-dialog-leaving`, so nothing counts it as an open dialog.
- **Slider reset**: `defaultValue` makes a double click reset the slider; without it a double click does nothing.
- **Focus**: a click never leaves a control highlighted. Focus rings are for the keyboard (`:focus-visible`); a
  field being typed into keeps its blue ring, since it shows where typing goes. Checkboxes, switches and sliders
  are left out of the fields' focus rules. Browsers count a clicked `<select>` as keyboard-focused (it takes
  typing), so the select menu marks one opened by the pointer (`data-by-pointer`) until a key is pressed on it or it
  loses focus.
- **Services**: each kit component starts the shared service it relies on (`Segmented` the knob, `Select` the menu,
  `Slider` its gestures, the buttons the tooltips), so it behaves the same anywhere, `/kit.html` included.
- **Kbd**: keys are written the Windows way; on a Mac `keyLabel()` shows glyphs in the order ⌃⌥⇧⌘ (Del ⌫,
  Enter ↩, Esc ⎋). **Separator** is the 1×20px rule between toolbar groups; **Spacer** takes the free room.
- `tests/legacy-ui.mjs` (part of `npm run check`) counts hand-written control markup per file against
  `tests/legacy-ui.json` and fails when any count grows.

## Appearance
- Appearance is System / Light / Dark (a deliberate override of HIG dark-mode.md), an icon-only segmented control (monitor, sun, crescent moon) at the right end of the top bar. At ≤1100px only the current icon shows and clicking it cycles System → Light → Dark. The choice is stored in localStorage `diagramtex.theme`; an inline head script resolves it to `data-theme` on `<html>` before the CSS loads, and System follows `prefers-color-scheme`. Dark redefines the same tokens on `:root[data-theme=dark]`.
- The drawing sheet, page sheets and the typeset document page stay light (`--canvas`, softened in dark) so user colours read correctly; `.doc-page` re-declares the light tokens for everything drawn on it.
- `prefers-contrast: more` strengthens rules and promotes `--pencil` to `--graphite`.

## Depth and shape
Hairline rgba rules and rounded corners: `--r-sm` 4px, `--r` 8px (buttons, inputs, segmented tracks, menu rows), `--r-lg` 12px (popovers, menus, cards: a row sits 4px in, 8 + 4), `--r-xl` 20px (modals: their head buttons sit 12px in, 8 + 12). Corners nest concentrically: a shape inset N px inside another takes the outer radius minus N. Segments are 3px inside an 8px (`--r`) track with 3px padding (radius `calc(var(--r) - 3px)`, 5px). Menus (context, select (with the dash, width, tip and shaft pickers), LaTeX autocomplete) have 4px padding and `--ctl` 28px rows with `--r` 8px corners inside a `--r-lg` 12px shell (8 + 4). Select rows sit 4px apart, the menu's padding; context-menu rows touch, split into groups by `hr` rules. Selected rows are marked by fill, not an edge bar, because a bar does not sit well on a rounded row. Every menu (context, select) highlights the hovered row the same way: the `--well` tone, text and icons unchanged; destructive rows turn the red pen. Submenus sit 4px clear of their parent, first row level with the row that opened it, with no icon column. Tool flyouts have 8px padding on every side and 16px corners (`calc(var(--r) + 8px)`: their 8px buttons + 8), section titles inset 4px. A flyout taller than the window stops 8px from its top and bottom and scrolls inside (`overscroll-behavior: contain`); its scroll bar is a thin 4px thumb (a 10px bar with a 3px clear border) whose track stops 14px short of each end, so it never runs into the rounded corners. The Export popover's controls (format switch, Download button) sit 12px in, so its shell takes 20px corners (`calc(var(--r) + 12px)`, 8 + 12), not the 12px of a menu. Modals (`--r-xl` 20px) work the same way: their head buttons sit 12px from the right edge. Square corners were tried and rejected as less friendly; chamfered (diagonal-cut) corners were considered and not used.
- Shadows are used only where something floats above the sheet: popovers, menus, the colour picker, modals, the inline editor and the document page.
- Menus open below their control (above when there is no room) and line up with the edge nearest the window side the control sits on: in the properties panel and the Export popover, the menu's right edge meets the control's right edge and the menu grows left; elsewhere the left edges meet.
- Elevation goes paper → sheet → sheet-raised.
- **Switches** (on/off settings such as the PDF export's Flatten): a checkbox with `role="switch"`, 28×16 track (`--rule-strong` off, `--ink` on) and a 12px `--sheet-raised` knob that slides 220ms `--ease`; the label sits left, the switch right, the whole row clickable. A setting the switch reveals (Flatten's Resolution row) appears after the knob has slid.

## Typography
The UI uses only two families: sans and mono. The serif (`--font-tex`, KaTeX_Main) is kept for content: text on the canvas (`.tx`) and the typeset document page (`.doc-page`). Never use it for UI chrome.
- **UI:** Atkinson Hyperlegible Next at 13px, a variable font served from `public/fonts/` (Latin and Latin Extended, normal and italic). Thai, in either interface language, is drawn in Sarabun (`fonts/sarabun-thai-*.woff2`, OFL, Thai-only `unicode-range`, Medium to ExtraBold with Medium also answering 400, at 105% so its x-height meets Atkinson's), placed after Atkinson in `--font-ui` and `--font-mono`, so Thai looks the same on every platform. The normal weight is Medium: its `@font-face` rules declare weights 500–800, so text set at 400 (the `font:` shorthand's default) is drawn at 500; 600 and 700 lead as SemiBold and Bold. The Latin files of both families are preloaded and all (Sarabun too) are precached by `sw.js`, so the chrome looks the same on every platform. It is drawn at 106% (`size-adjust`): at the same font size its lowercase was 4% and its capitals 9% shorter than Inter Display's, which the type scale was set with. It is also wider: the Table toolbar is full at 1400px, so its style select is 104px (the longest name, Academic, is about 61px of the 72px inside).
- **Section titles** (`.sec-title`, `.pop-title`, `.panel-head span`, `.sc`): 11px, weight 600, sentence case, in pencil.
- **Type scale:** 10 (rulers, captions) · 11 · 12 · 13 (body) · 15 (titles). Nothing below 10px (HIG macOS minimum).
- **Labels:** buttons, menu items and dialog titles use title-style capitalisation; checkbox labels and hints use sentence case. On macOS, shortcuts show as glyphs in the order ⌥⇧⌘.
- **Thai text fonts (content, not UI):** Garuda, Kinnari and Laksaman (TLWG, `fonts/tlwg-*.woff2`, GPL with the
  font exception) are text fonts in `TD.FONTS`, named "Garuda (ครุฑ)" etc. and previewed in their own face. They are
  for viewing only, with no LaTeX command (export keeps the document's font). They load when text first uses them,
  and text measured before then is measured again (`loadingdone` clears the text cache and redraws).
- **Numbers and code:** Atkinson Hyperlegible Mono (`--font-mono`, served with the app, full weight range, drawn at 106% like the UI font so it stands as tall as the labels beside it; it is wider than SF Mono was, so check narrow value fields) with tabular-nums for numeric inputs, the status line, rulers and the doc HUD, and in code fields.

## Spacing and measurements
- 4px base.
- Top bar: two 44px rows (`.doc-row` with the name, `.tools-row` with the tools) with 28px controls (8px above and below); toolbar groups are separated by space, not rules; one prominent action (TikZ).
- Tool rail 48px with 32px rounded buttons; a tool group (the buttons with a corner mark) opens its flyout when the mouse rests on it for 120ms and closes it 280ms after the mouse leaves both button and flyout, so the 6px gap can be crossed; moving to another group's button switches at once, and its tip doesn't show while the flyout does. A click keeps the flyout open until a choice, a click elsewhere, Escape or a second click; touch and pen still tap. document list 200px with inset 28px rows (each with a 14px line icon for its kind: a Classic document is an outlined page whose top-right corner is cut diagonally with a square-drawn fold, never a filled page), which the top-bar toggle folds open and shut in 240ms (its rows clipped, not rewrapped, and the drawing held still on screen, same place and scale, so the list only covers or uncovers its left side; instant under reduced motion); properties panel 280px (`--props-w`) with 12×16 section padding and an 84px label column. The panel is a floating window (12px corners, pop shadow) 8px in from the top right of the canvas, below the ruler and above the status bar, so the canvas runs the full width beneath it; its first heading (which names what is selected) is lifted out of the scrolling part into the window's head, so the scroll bar starts below it; the whole head is clickable (pointer cursor) and folds the window up to that heading or back down, easing its height over 240ms, with a chevron at its right (∧ open, ∨ folded) as the keyboard and screen-reader control. Folded or open is remembered. Stacked full-width buttons in it are 8px apart.

## Selection language
- **Marquee**: drag left-to-right for a window selection (shapes wholly inside; red-pen dashed box). Drag right-to-left for a crossing selection (anything whose drawn outline or fill the box touches, not just its bounding box), shown in highlighter yellow (`--marker`).
- **Selection box:** red pencil, 1px, dashed 4/3.
- **Group box:** red, dotted 1/3.
- **Into a group:** the first click on a member selects the whole group; a second click (no drag) on a member selects it alone, and while inside, a click on a sibling selects just that sibling. A drag from a selected group still moves the whole group. Pasting a lone member drops its group id.
- **Main handles:** 7.5px squares with a white fill and red stroke.
- **Control points** (curves, plots, CD arrows): blue circles.
- **Marquee:** red wash with a dashed edge.

## Cursors
- Use the standard CSS cursor for what a drag will do. Never `pointer` (the hand) on canvas handles: the hand is for links and buttons.
- Edge and corner handles resize: `ew-`, `ns-`, `nesw-` or `nwse-resize`, turned with the shape's rotation and snapped to the nearest of the four. Text wrap and circle radius handles count as edges.
- The curvature pen (`curvpen`) draws through `polyDraft` too: a `poly` with `smooth`, `curv: true` and an optional `corner` array (1 per corner point, kept in step by insert, remove and the duplicate filter on finish). Its segments come from `curvSegs` in src/domain/shapes.ts (`TD.polySegs` picks it by `curv`): a smooth point's tangent is that of the circle through it and its neighbours, and each handle is 0.3905 × its chord × (cos α / cos 45°)^¼ (α between tangent and chord), fitted to Photoshop's output to about 1px. Curve through points and smooth closed curve set `tension: 0.5` and are TikZ's `plot[smooth]` exactly (`smoothSegs`: handles ± 0.2775·tension·(next − previous), open ends' handles on the ends), exported as `plot[smooth(, cycle)] coordinates` with a `tension=` other than 0.5. The panel's Tension field (number, min 0, step 0.05) shows only for shapes that have `tension`; smooth shapes without `tension` keep the old Catmull-Rom (k = 1/6) and their `.. controls ..` output. While drawing, placed points are `.arc-pt` marks, round for smooth and square for corners, and a `.snap-ind` ring sits on the first point when a click would close the path; double-click and Alt-click make corners instead of finishing. Selected, its smooth points are round handles and its corners square; the + sits on the curve (`polyMid`); double-click switches smooth/corner and Delete removes the chosen point (on other polylines a double-click still removes it).
- Arcs are drawn click by click (`arcDraft` in src/application/app.ts, like `polyDraft`): Arc by centre (`arc`, O) takes the centre, the start, then the end, with the sweep summed as the pointer turns so it goes either way and past 180°; Arc through three points (`arc3`) takes both ends, then a point on it (circumcircle; nearly straight shows no arc yet). Both make an ordinary `arc` shape. The first step can be a drag. Guides are `.guide` lines with `--bluepen` `.arc-pt` dots; the status hint changes at each step; Esc or another tool cancels. Once drawn, the end handles (`a1`, `a2`) set only θ1 and θ2 (the radius stays), the `rad` handle halfway along sets the radius (resize cursor along the radius), `rx` and `ry` sit on the middle of the far sides of the arc's bounding box and stretch it across or up and down (relative to the grab, so a handle nudged 14px out never jumps; nudged only when it would sit on another handle; Shift returns it to a circle), and `c` moves it. `ry` is optional on the model: absent means round, and θ1/θ2 become TikZ's parametric angles. Geometry shows `rx`/`ry`. Handles on the circumference (`a1`, `a2`, `rad`) are circles (`round: true` on the handle → `<circle class="handle">`, red pen like the squares); the edge handles stay squares. Arcs rotate: a round arc shifts θ1/θ2, an elliptical one keeps `angle` (its axes, counter-clockwise; TikZ `rotate around={angle:(c)}`), and its selection box, edge handles and rotate zones use its own box turned with it (`T.arc.frame`). Making it round again folds `angle` back into θ1/θ2.
- Point handles (line ends, vertices, arc ends, arc centre) and shape bodies: `move`. Space held: `grab`; while panning: `grabbing`. Rotation zone: the custom rotate cursor. A single block whose content never turns (plot, CD, chemfig, timing, the 3D figures…, `FIXED` in src/application/app.ts) gets no rotate zone, no Rotate menu item and no "rotate, flip" in the panel hint; Ctrl+R does nothing. Two or more selected objects can still be turned about their centre. The zone is a small tab straight out from the middle of each edge (28px wide centred on the edge's midpoint, narrower on a short edge; 9–26px out along the outward normal). A strip along the whole edge was tried and felt too greedy, as was a radial zone around the corners. It stays 9px clear of the resize handles the shape actually has, so a near miss on a handle still resizes, and it never covers another shape: pressing on another shape selects it.
- During a handle drag the canvas keeps the handle's cursor, so it doesn't flicker when the pointer outruns the handle.

## Rendering at scale (`render()` in src/application/app.ts)
- A shape's markup does not depend on the view: hit outlines take their width from `--hitw` (14 screen px, set in `applyView`). Pan and zoom call `renderView()`, which only moves the view.
- Markup is remembered per shape against its JSON (`drawn`); only shapes whose markup changed are put back into `#content` (`paintContent`). Lines that hop over others are always redrawn. Fill defs live in `#contentDefs`.
- Over 400 shapes, only those within one view's width and height of the view are in the canvas (`paint`); leaving that margin, or zooming in 3×, paints again. Selection outlines off screen are skipped too.
- Text sizes are measured in one layout pass per render (`TD.measureBatch`): measuring one at a time forced a layout of the whole canvas each time. `TD.measuring()` is true only once that pass has handed out a placeholder size; until then every size is real, so a redraw with nothing new to measure keeps each shape's markup (`drawn`) and each block's layout. When it was true for the whole pass, nothing was kept and every frame drew every label again (300 maths labels: 281 ms → 0.9 ms per redraw). The maths picture cache (`label-image.ts`) is least-recently-used and bounded by the pictures' total size (32 M characters, at most 16384 entries), so a drawing or table with thousands of labels stays cached. Once `TD.measuring()` is true, label pictures are not built at all (`textSvg`, the table's `fo`): that pass is drawn again with the real sizes.
- A maths label is an SVG `<image>`; a new picture decodes asynchronously. When the same text is redrawn (a new wrap width while resizing, a size or colour), the label keeps its current picture until the new one has decoded (`SvgLabelResources.assign`, `updateSvg`), so it never paints a blank frame. Pictures commit in order as each decodes, so a fast drag still follows the pointer. Other text in a reused element swaps at once. `tests/label-swap.mjs` checks it.
- The rulers' ticks are redrawn with the view (`drawRulers`); a pointer move only moves the pointer mark (`moveRulerCursor`).
- `syncPos` (nodes placed relative to another) looks names up in one map per render, not by searching every shape.
- The Layers panel rebuilds only the rows whose markup changed (`layerEls`); the others keep their elements.
- Block editors draw through `patchSvg` (`src/ui/svg-patch.ts`): their markup is split into top-level elements and compared as text with the last draw, so a pan keeps every element (label pictures included) and only moves its group; `tests/suites/89-editor-patch.js`.
- The Table workspace's maths: each progress round redraws only the cells waiting on a formula that just finished (`data-math-pending` ids, passed to `TD.math.onProgress`), reads their fades once after all writes, and redraws the preview picture (not the LaTeX) at most every 250 ms, patched with `patchSvg` and skipped while its tab is hidden (opening the tab catches up). Pending cells within the grid's view are ranked 0 and a view's height around them 1 (`rankVisibleMaths`, after each paint and on scroll), so what is on screen fills in first.
- The maths queue (`src/platform/math-render-queue.ts`) sends the worker batches of about 8 ms of work (at most 64, in priority order, one batch in flight), publishes as many results a round as the views keep up with (2 to 512, doubling while a round takes under 8 ms, halving over 24 ms), rests twice a round's cost before the next (a round's fixed cost, the views' bookkeeping, layout and paint, is paid per round, not per formula), and keeps results by total size (24 M characters, at most 16384). 1,500 Temml cells in a table: 254 s → 9.3 s, the visible ones in 0.4 s.
- Long work never blocks input. In a preview draw (`TD.math.preview`), KaTeX compiles at once for the first 12 ms and queues the rest for the worker. A big drawing's label pictures are made within `labelBudget(ms, draw)` (`src/domain/label-image.ts`): those past the budget come back as placeholders with a `later` number, drawn as pending, and the Table preview makes them a frame's worth (10 ms) at a time in place (`laterPicture`), without redrawing the table. Pending view work (`TD.math.trackView`, including a preview still to come) keeps the picture outputs disabled. 1,500 KaTeX cells: one 2 s freeze → worst task about 200 ms (the first preview measuring every new cell), p95 input lag 80 ms.
- `byId` keeps an id index; snapping while dragging uses a grid of the other shapes' anchors.
- Dragging more than 200 shapes (`FAST_DRAG`) leaves them untouched until the drop: their painted elements get the class `mv` and slide by `--mx` / `--my` on `#content`, `#overlay` slides by a transform, and only connectors attached from outside are redrawn (`fastMove`, `fastLinks`). The selection snaps by its bounding box's corners, edge middles and centre. On release each shape is translated once (`endFastMove`).
- **A Classic document's page** has its own undo (`src/application/doc-history.ts`, ⌘Z / ⇧⌘Z in Document view, also inside a text block, a table cell or the LaTeX source): adding, moving, deleting and editing blocks, and the page setup. A step keeps only the blocks it changed, as JSON, with the block order before and after; blocks are known by identity, so undo leaves alone a diagram edited on the canvas since (that has the diagram's own undo). Every change goes through `changed()` in docview; each render takes the document as it is as the new starting point. Typing in one place (a text block, a cell, an image's width) within a second is one step, and undo reopens that block with the caret where it was. 200 steps or about 40 MB.
- Undo steps hold only what changed (`commit`): changed, added and removed shapes as JSON before and after with their list positions, the whole id order only when shapes were reordered, and a Page file's page count. `base` keeps the drawing as of the last step as JSON per shape, so `begin()` costs nothing. Undo keeps 300 steps or about 40 MB of text, whichever is less (at least 5).
- Files and the file list (`diagramtex.doc.*`, `diagramtex.index`) live in IndexedDB (`src/platform/storage.ts`, database `diagramtex`, store `kv`), read into memory at start so the app reads them synchronously; writes are batched into one transaction and broadcast to other tabs. `init()` waits for it and the loading screen waits for `TD.ready`. Files found in localStorage move in at start. Without IndexedDB everything stays in localStorage. A write that fails is shown in `#saveState`.
- Browser storage keys and the file signature are `diagramtex` (`app: 'diagramtex'`; earlier exports carried a `% diagramtex-data:` comment, which the importer still reads, but no export writes it now: one base64 line passed TeX's line limit and stopped pdflatex). An inline script (`src/platform/preflight.ts`, inlined into `index.html` at build) moves `texdiagram.*` keys to `diagramtex.*` once; the importer reads both comment names.

## Files sidebar

Rename/Duplicate/Save As/Copy/Paste/Delete work on that file in place; Download/Export/Print open it first, since they act on the open file.
- Rename… turns the row's name into a field in place (Enter or clicking away keeps it, Esc cancels); the file isn't opened, and the top-bar name follows when it is the open file. With the sidebar hidden it falls back to the top-bar name field.
- Right-click the empty list area: New, Open File…, Paste; Export All Files… (one `.diagramtex` bundle, `kind: "bundle"`, `files: [...]`; opening it adds each file to its kind and shows a count in the hint, without opening any).
- Copy puts the project JSON (same as Download) on the system clipboard; Paste opens it as a new file and never reuses an existing name ("… copy", "… copy 2").

- **Sort** (`#btnSortDocs`, a sort line icon left of New in the list's header): a `.ctx` menu of menuitemradio rows that opens on hover (`HOVER_OPEN`/`HOVER_CLOSE`) or a click; a choice closes it on release. Clicking the button keeps a hover-opened menu open (it no longer closes when the pointer leaves); a second click closes it. It sits with its right edge on the button's so it sits over the sidebar. Rows: Custom order, Date created, Date modified, Name; a rule; the direction, labelled for the key (A to Z / Z to A, Oldest first / Newest first) and disabled for Custom order. Stored in localStorage `diagramtex.fileSort` (`{by, dir}`). The button is ink while a sort other than Custom is on, wash while its menu is open. Index entries carry `created` (set when a file is made, imported or copied; kept through the bin); older entries count as created when last modified. Sorting applies inside each folder; folders sort by name (reversed with Z to A) or by their newest file under the date sorts. Dragging rearranges only in Custom order (the blue-pen line between rows); sorted, dragging still moves files into or out of folders. The closed menu holds no rows.
- File and folder rows are 4px apart (`#docList` gap), so a hovered row and the open one never merge into one block.
- Folders are names with "/" (S3-style paths), nothing stored apart: a folder exists while a file is in it. Folder rows come first (A to Z), indent 16px per level (`--depth`), chevron rotates 220ms; folded state is a preference (`diagramtex.folded`, `kind:path`). Right-click a folder: New … Here, New Folder Inside…, Rename Folder… (in place), Fold/Unfold, Delete Folder… (red). Drag a file onto a folder row to move it (blue-pen inset ring on the target).
- Delete moves to the **Recycle Bin** (`diagramtex.bin`: `{id, name, kind, deleted, folder?, batch?}`; the doc data stays under its key). No confirmation for one file (it can be restored; the hint says where it went); a folder asks first. The bin row sits under the list (quiet, count in mono); its dialog (ui/BinDialog.svelte) is a `.tdd-box` that fades in and out like the confirm dialog, with one row per file or per deleted folder, Restore (wash fill) and a trash icon that turns red pen; Empty Bin… bottom-left, Done primary. Items older than 30 days are erased at start-up and when the bin opens. **Undo history is per file** (and per diagram of a Classic file): switching keeps each one's steps for the session (newest 40), and they come back only if what they apply to is unchanged (another tab's edit, a restored recovery copy, an import over the file or reordered blocks drop them). Every step carries one app-wide clock, so ⌘Z takes whichever is later, the open file's last step or the last delete; ⇧⌘Z takes whichever was undone last. A delete is an undo step: ⌘Z takes the files back out of the bin to their old places in the list (and reopens the file that was open, with its steps, dropping the untouched blank file that stood in for it), ⇧⌘Z deletes them again and returns to the file undo was pressed in; a delete whose files were since restored or erased is skipped and undo goes on to the step before it; in Document view the page has its own steps (`src/application/doc-history.ts`), which take turns with the file list's by the same clock. The hint after a delete names the shortcut. A file restored or erased from the bin dialog since is no longer an undo step.
- **Recovery copies** (`src/core/recovery.ts`, `diagramtex.rec.<id>` in IndexedDB, newest first: `{taken, at, doc, recent?}` without the view). Not versions: autosave keeps the state a file had before a change, at most once a period, and only the newest few. When the period is longer than 5 minutes (`RECOVERY_QUICK`), one more copy (`recent: true`) is taken every 5 minutes in between and the next one replaces it, so a file has `keep` + 1 copies at most; a period's copy leaves it, and Never turns both off. Settings (`diagramtex.recovery`: `every` minutes 0/1/5/10/30/60, default 10; `keep` 3/5/10/20/50, default 3) live in the dialog itself, opened from the file's right-click menu (Recovery Copies…, history icon) or the command search. The dialog is the bin dialog's shape: rows with the copy's time, age, contents and size, Restore (wash) and an icon button that opens it as a new file named "Name (Today, 12:36)"; the two selects under a rule; Done primary. Restore writes the copy over the file but keeps its name, view and list place, and first keeps the current state as a copy, so it is undone by restoring that one. Copies go with the file when it is deleted for good.
- Share link: `#share=1.<deflate-raw base64url>` (`0.` = uncompressed fallback), its numbers written to 6 significant digits (`shareNum`: off-grid coordinates shrink, typed values like 0.125 pass unchanged; a third off a hand-drawn board), at most 8,000 characters, else an alert says to send the file. Opening one adds a copy (or opens an identical existing file) and clears the hash.

## Lines flyout and connectors
- `#fly-lines` follows PowerPoint's order in two titled rows of seven: **Lines** (line, arrow, double arrow, elbow connector, curved connector, Bézier curve, curved arrow) and **Freeform** (curvature pen, curve through points, polyline, smooth closed curve, arc by centre, arc through three points, spring). One elbow and one curved tool, not one per arrowhead: tips are set in the panel.
- A connector is a `line` with `route` ('elbow' | 'curved'; none = straight) and `dir`, two letters for how it leaves and arrives (`h` sideways, `v` up/down; `hh` ⌐, `hv` L). Without a `dir` it follows the line's longer side. An elbow's middle segment is put at `mc`, a fixed x (hh) or y (vv) in the drawing (halfway until first set), with `ms` the side it was put on (`lo` / `hi`: beyond both ends, `mid`: between them) and `mr` how near each end may come (20px / 0.5 cm, or less if it was put nearer). It is drawn at `mc` unless an end has come nearer than that, then just clear of it (`TD.elbowMid`); nothing is written back, so it springs back when the end moves away. A middle never put anywhere is fixed where it is drawn the first time an end moves (`TD.keepElbowMid`). The handle is a blue control with an `ew-resize` / `ns-resize` cursor. When its ends are level (`TD.elbowFlat`), dragging it flips the dir (hh ↔ vv) and pulls the middle out into a U. Moving the line itself moves `mc` with it. A lone elbow is not `turnable`: no rotate zone, ⌘R does nothing and the menu's two Rotate items are disabled, but Flip still works (in a mixed selection it turns with the rest). A quarter turn swaps h and v and keeps the middle where the turn takes it (`TD.placeElbowMid`). The label sits on the middle segment (an L: the longer one). Curved = TikZ `to[out, in]`, drawn with TikZ's controls (0.3915 × the distance), so canvas and PDF agree. Crossings (hops) are offered for straight and elbow only.
- Every line tool (line, curve, spring families) draws by a drag or by two clicks, and so does any shape a click alone can't size (the rectangle and ellipse in their drag modes; `clickMakes` runs the type's `fix` on a copy, so symbols, which take a default size, still place with one click): a press that doesn't move 4 screen px leaves `lineDraft`, whose end follows the pointer (snapping and attaching as in a drag) until the next press; Esc, right-click or a tool change cancels it.
- **Draw modes** (`DRAW_MODES` in src/application/app.ts, remembered in `diagramtex.drawModes`): the plain Rectangle and Ellipse buttons lead the Basic shapes row of `#fly-shapes`; they carry the rail's corner mark and show their current mode's icon. Resting on one for 120ms (or right-clicking it) opens `#modeMenu` 4px below it, left edges in line: a `.ctx` menu (z-index 45, over the flyout) of 20×20 line icons with filled dots for the points you place, labels, and the context menu's tick (`svg.ck`, `menuitemradio`) on the current mode. It belongs to the flyout: being over either keeps both open, with the same 280ms grace. A choice sets the mode and takes the tool. Drag modes go through the type's `drag(s, a, q, e, mode)`; click-by-click modes (rectangle by three points, circle by three points) share the arc tools' draft (`pointsKind`), with the same guides, hints and Esc.
- Panel: **Route** and **Direction** are icon switches (`type: 'icons'`, `.seg-ctl.fill`: the buttons share the field's full width, 18px icons); Direction draws its four choices the way the current route bends. Direction only shows for elbow and curved lines.

## Interface text (`src/i18n`, see docs/interface-languages.md)
- On first access, the primary browser language chooses Thai for `th` / `th-*`, English otherwise. Saved language choices take precedence. Detection uses browser preferences only, with no location or network lookup.

## Dialogs (`src/ui/services/dialog.ts`)
- Never use the browser's `alert` / `confirm` / `prompt`. Use `TD.confirm(title, message, opts)`, `TD.prompt(title, value, opts)`, `TD.alert(title, message)`; each returns a Promise.
- The title asks the question ("Delete "Name"?"); the message says what happens. Buttons name the action ("Delete", "Save", "Add Link"), never "OK" when a verb fits.
- Destructive actions pass `danger: true`: red button, focus starts on Cancel, so a stray Return can't delete.
- A prompt whose text is typeset passes `preview: (value) => html`: a read-only `.tdd-pv` box (`--well`, `--font-tex`, centred) under the field shows it as typed. The Classic document's title uses it: double-clicking the title opens **Rename File** (the message says the title is the file's name and how to write maths), and the file keeps its folder.
- Esc cancels, Enter takes the default, Tab stays inside, focus returns to where it was. One dialog at a time.
- **Welcome tour** (`src/ui/services/tour.svelte.ts`, `.tour-box`): five cards on the dialog sheet (Welcome, left: files, tools and Blocks; top: the kind switch, Export and LaTeX; right: the panel; keep a copy: browser storage can be wiped, Save as `.diagramtex`). The card is 500px wide, with a 17px title, 14px text and 32px buttons. Each card has a 280×140 map of the window (`.tour-map`) with its part marked in blue pen (`.zone.on`, 14% wash and a 1.5px line), so the real page is never covered or moved. The buttons are **I’m All Good** (plain, left, sitting `--tdd-inset` from the left as **Next** does from the right, so both nest in the card's corners; hidden on the last card), progress dots, **Previous** (hidden on the first card) and **Next**, which says **Got It** on the last. All use `visibility`, and `.tour-body` has the longest card's height, so the card and its buttons stay put. Keys: ← → step, Esc closes, Tab stays on the buttons. The card is src/ui/Tour.svelte (kit Buttons); it opens and fades out as the kit's dialog does. It is shown once, on the very first visit (no files yet, `diagramtex.tour` unset; the key is set when it opens), and again from the command search (**Welcome Tour**). The test runner sets the key before the page loads.
- A prompt's field belongs to the person: it gets the starting text once (`initial` in Dialog.svelte) and nothing writes it again. Never `liveValue` here. It puts the model's text back on blur, and pressing a button with the mouse blurs the field first, so the typed text was lost.
- Buttons sit the same distance (`--tdd-inset`, 14px) from the right and bottom edges, and the sheet's corner is concentric with theirs: radius = button radius + inset (`calc(var(--r) + var(--tdd-inset))`, 8 + 14 = 22px). Text keeps its 20px inset.

## Attached connectors
- Lines, arrows, curves and springs attach an end that is dropped on a shape's outline or one of its snap points. The end is stored as a position in the shape's frame (`link1` / `link2` = `{ id, u, v }`) and follows the shape when it moves, resizes or rotates.
- While drawing or dragging an end, the shape it will attach to gets a soft blue outline and the end snaps onto the outline. Attached end handles are filled blue.
- Moving, nudging or rotating the connector without its shapes detaches it, as does typing an end's coordinates or dragging the end off. Alt places an end without attaching.
- Copies keep links only to shapes copied with them. TikZ export uses plain coordinates.

Duplicate still offsets from the original.
- Command suggestions follow the caret: inside maths, every command; in prose, only commands that work in text (`TD.prose.textOk`: the prose commands and symbols, `\text…`, sizes, spacing, refs).
- In quantikz code (the canvas code editor and the panel's code field) suggestions follow the circuit: at cell level the quantikz commands (Gate, Control, Measure, Wire, Label, Group), each previewed as a small drawing by the circuit renderer itself in the UI's ink (`TD.qcMini`; gate fills use `--qc-paper`, the row's own opaque colour, `--wash-strong-solid` when highlighted); inside a command's `{…}` every maths command; inside `[…]` none. `&` and `\\` reset the context, so a half-typed bracket doesn't leak into the next cell.

## Quantum circuits (`src/domain/quantum.ts`)
- Blocks → Quantum. The object *is* its quantikz source: it is drawn as vectors (an approximation of quantikz2's layout, wires run the full width unless `\setwiretype` / `\wireoverride` say otherwise) and is edited in the quantum editor (`src/editors/qceditor.ts`, below). Placing it only selects it (blocks never open their editor on insert); double-click, Enter, the context menu's Edit or the panel's Edit Circuit… open it, and Done is one undo step. The panel shows the code, any commands that aren't drawn (kept in the code, red-pen lines), Edit Circuit… (primary) and Copy quantikz Code. A circuit with nothing drawn falls back to its grid's extent.
- Drawn: `\gate` (incl. `[wires=n]`, `\gate[…][min width][min height]{…}`, which widens the column, and `style={minimum width/height/size=…}`, which grows only the box, over its neighbours, as quantikz does; the panel warns about that and about `$` inside a gate, which quantikz already sets as maths), `\ctrl \octrl \control \ocontrol \targ \targX \swap \phase \meter \meterD \measuretab \lstick \rstick` (incl. braces for `[wires=n]`), `\push \midstick \qw \cw \qwbundle \setwiretype \wireoverride \wire[d|u|l|r][n]{q|c} \vqw \vcw \cwbend \slice \gategroup \ground`, and `row sep` / `column sep` / `wire types` options. Gate contents are maths (with or without `$`); stick, slice and group labels are text (a bare command such as `\ket{0}` in a stick is maths, as it is in LaTeX). `\setwiretype` also sets the wire coming into its own cell, as quantikz2 draws it.
- Geometry is calibrated against compiled quantikz2 (TeX Live 2026): row and column sep 0.5cm between cell edges, everything `thick`, gates are their text plus 4pt a side, meters 2em × 1.5em, control dots 0.12cm, stick labels hang off a zero-width column, slices red and dashed 5pt/3pt, gategroups solid with 4pt + ⅓em to spare and their label 0.2cm above. The compiled circuit lands within about 1mm of the drawing.
- Export: `\usetikzlibrary{quantikz2}` and the code unchanged in an option-free `\node` (options would leak into the circuit's nodes), centred on the drawing, inside `\pgfinterruptpicture`. Import turns a bare `\begin{quantikz}` or one inside a `\node` back into the object.

## Maths rendering and scene coordinates

- KaTeX uses its original HTML output in all browsers. Temml parses to MathML; MathJax 4 lays that MathML out as self-contained SVG paths using bundled TeX font data. No native-MathML fallback or browser-specific layout offsets are used.
- The shared renderer resets inherited UI language on formula roots (`lang=""`). Locale changes must preserve source, metrics and painted formula pixels.
- `label-image.ts` finishes HTML layout inside an origin-based SVG image with embedded font faces. The scene applies its transforms to the whole image, so positioned accents cannot escape the label's coordinate system. Tables and diagrams use the same boundary. Plain prose can remain a simple foreignObject.
- All bundled font faces load before first measurement. `document.fonts.ready` alone cannot discover fonts not yet used by a formula. Both browsers must match the same export goldens.
- `npm run test:parity` compares 180 cases; `npm run test:rendering` checks actual ink bounds and hats/vectors following their bases through pan and zoom. Keep the original parity tolerances.

## Document zoom and page boundaries

- The Classic document lays out at 100% in a fixed paper width. `.doc-sheet` provides the scaled scroll dimensions and clips the unscaled layout overflow; its `.doc-page` scales from its top-left with a CSS transform. Font size, wrapping and content coordinates never depend on zoom.
- In-flow editors, the table and image formatting bars and insertion controls scale with the paper (the text toolbar sits outside the paper and does not). Only the absolutely positioned block actions counter-scale, using a transform rather than CSS zoom so they cannot move the content or page dividers.
- Page count uses unscaled block offsets and exact CSS centimetres (96 / 2.54 px); divider positions stay in paper coordinates. Print removes the screen wrapper sizing and transform. `npm run test:document` checks WebKit and Chrome at zoom limits, on resize and in print media.

- In Document view, reserve at least 16px for the outer scrollbar, plus the panel's 8px gap. Native scrollbar gutters are measured on `#docview`; overlay scrollbars receive the missing space through padding. `#rightCol` stays outside that strip, and the fixed paper layout remains unchanged.
